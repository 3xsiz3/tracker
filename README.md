# Трекер развития навыков

Веб-приложение для постановки и отслеживания задач развития сотрудников. Руководитель ставит
задачи на развитие конкретных компетенций, сотрудник отчитывается о прогрессе, а по завершении
проходит проверку и получает оценку — из оценок складывается профиль навыков сотрудника и
аналитика по команде.

## Возможности

**Руководитель**
- Постановка задач развития с привязкой к компетенции, сроком и чеклистом условий выполнения
  (разбивку делает сам или делегирует сотруднику)
- Проверочные вопросы к задаче: открытый вопрос или мини-тест с вариантами ответа —
  сотрудник обязан ответить до принятия задачи
- Подтверждение выполнения («На проверке» → «Принять») и многокритериальная оценка
  (качество, сроки, самостоятельность, 1–5)
- Дашборд «Команда»: сводка, задачи требующие внимания (на проверке / просроченные),
  карточки сотрудников с оценками и активностью
- «Отчётность»: завершения по неделям, средние оценки по компетенциям, сводная таблица
  по сотрудникам
- Удаление задач

**Сотрудник**
- Список своих задач с фильтрами по статусу
- Отметка выполнения условий чеклиста (прогресс считается по весам пунктов)
- Ответы на проверочные вопросы руководителя
- Личная сводка: статусы задач, средняя оценка, профиль навыков по компетенциям

**Общее**
- Комментарии к задачам, история изменений прогресса
- Статусы: Не начато → В процессе → На проверке → Завершено (после подтверждения руководителем)

## Стек

React 19 · TypeScript · Vite · React Router 7 · Zustand · Tailwind CSS 4 · shadcn/ui (radix-ui) ·
date-fns · lucide-react · [Supabase](https://supabase.com) (Postgres + Auth) как бэкенд.

Фронтенд — статическая SPA-сборка, вся работа с данными идёт из браузера напрямую в Supabase
через `@supabase/supabase-js` (`src/lib/supabase.ts`). Своего сервера/бэкенда нет: доступ к данным
регулируется Row Level Security-политиками в БД (см. `supabase/schema.sql`), а не серверным кодом.

## Запуск (разработка)

1. Поднять проект в Supabase и выполнить `supabase/schema.sql` — см. «Развёртывание» ниже.
2. Скопировать `.env.example` в `.env` и подставить `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`
   из Project Settings → API вашего Supabase-проекта.
3. Завести хотя бы одного пользователя (Часть D в «Развёртывании»).

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # прод-сборка (tsc + vite build) -> dist/
npm run lint      # oxlint
```

`src/store/seed.ts` — не используется в приложении, оставлен как справочный пример структуры
данных для ручного заполнения БД.

## Развёртывание (Supabase + любой статический хостинг)

### A. Supabase-проект

1. Зарегистрироваться на [supabase.com](https://supabase.com), New Project → выбрать регион
   Frankfurt (eu-central-1) → задать пароль БД (сохранить отдельно).
2. Project Settings → API → скопировать **Project URL** и **anon public key** в `.env`
   (или в переменные окружения хостинга, если сборка идёт там). Анонимный ключ не секретный —
   безопасность обеспечивают RLS-политики, а не сокрытие ключа.
3. SQL Editor → New query → вставить содержимое `supabase/schema.sql` → Run.

### B. Пользователи

Для каждого человека — Authentication → Users → **Add user** (email + пароль, включить
**Auto Confirm User**), затем добавить соответствующую строку в `public.profiles` — шаблон
с готовыми `insert`-запросами в `supabase/seed-users.sql.example`. Новые сотрудники заводятся
так же вручную — в приложении нет самостоятельной регистрации.

### C. Статическая сборка на хостинг

1. `npm run build` → папка `dist/`.
2. Залить **содержимое** `dist/` в корень веб-директории хостинга (`public_html` и т.п.) —
   через файловый менеджер панели или по FTP.
3. `public/.htaccess` (копируется в `dist/` при сборке) добавляет SPA-фолбэк для Apache —
   без него прямые ссылки на вложенные роуты (`/manager/reports`) и обновление страницы (F5)
   будут отдавать 404, так как маршруты обрабатываются на клиенте (React Router).
4. Подключить SSL (Let's Encrypt) в панели хостинга и убедиться, что домен указывает на этот
   хостинг.

### D. Финал

Supabase Dashboard → Authentication → URL Configuration → Site URL = адрес вашего домена
(используется в письмах сброса пароля и т.п.).

## Структура

```
src/
  pages/       — страницы (логин, дашборды ролей, сотрудник, задача, отчётность)
  components/  — компоненты (чеклист, вопросы, оценка, комментарии, диалоги, чарты)
  store/       — Zustand-стор (useAppStore) — тонкий клиент над Supabase
  lib/         — доменная логика: прогресс/статусы задач, агрегация навыков и отчётов, цвета,
                 клиент Supabase
  types/       — модель данных
supabase/
  schema.sql              — таблицы, бакет вложений и RLS-политики (для нового проекта — один раз в SQL Editor)
  migration-attachments.sql — миграция для уже развёрнутой базы: добавляет вложения к комментариям
  seed-users.sql.example   — шаблон для заведения реальных сотрудников
```

## Модель данных

- **DevelopmentTask** — задача: компетенция, исполнитель, чеклист с весами (сумма 100%),
  срок, история прогресса (с пометкой, какое условие отмечено/снято), проверочные вопросы,
  отметка подтверждения
- **ChecklistItem** — условие выполнения с весом; прогресс задачи = сумма весов выполненных
- **VerificationQuestion** — открытый вопрос или тест с правильным вариантом; ответ хранится на вопросе
- **Assessment** — оценка задачи руководителем по трём критериям; агрегируется в профиль
  навыков по `competency` задач
- **User / Comment** — пользователи (роль, руководитель) и комментарии к задачам, с файлами-вложениями
  (хранятся в Supabase Storage, бакет `attachments`, скачивание — по подписанной ссылке)

Таблицы в Supabase (`supabase/schema.sql`) названы в camelCase и повторяют эти типы один в один —
без слоя маппинга snake_case ↔ camelCase в коде.
